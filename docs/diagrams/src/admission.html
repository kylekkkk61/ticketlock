TicketLock · admission

One entry, two signatures, one transaction

A ticket is used only when its holder and the event's organiser approve the same request. Neither can do it alone.
1
Customer confirms
Scans the door code and presses Confirm entry. The phone signs an entry permit and shows a short code.
The ticket is still unused.
2
Staff admit
The same code appears on the organiser's screen. Staff match it to the person and press Admit.
The organiser signs the same permit.
The entry permit
  • Ticket which ticket, for which event
  • Holder the account that owns it now
  • Gate the event's organiser
  • Counter the ticket's current number
  • Expires two minutes after it was made

3
The relayer sends it
TicketLock's server puts the permit and both signatures into one transaction and pays the fee. It cannot change a single signed field: the signatures would stop matching.
4
The contract checks
  • The ticket exists and belongs to this event
  • It has not been used
  • The first signature is from its current owner
  • The second is from this event's organiser
  • Owner and organiser are different accounts
  • The counter matches and the permit has not expired
5
Used, with the time recorded
Final. The ticket stays with its holder as a record and can never be transferred or admitted again.
A copied door code
Does nothing. It names the event and carries no authority.
Staff acting alone
Cannot use up a ticket. The holder's signature is required.
The platform
Pays and delivers. It cannot forge either signature.
